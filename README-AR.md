# وين؟ — ميزات الطلب الجماعي والمحادثة والخريطة

هذه الإضافة توفر مخطط قاعدة بيانات لإرسال طلب الرحلة إلى كل السائقين والمكاتب المتاحين، مع آلية «أول قبول يفوز» داخل قفل قاعدة البيانات، وجدول محادثة مرتبط بالرحلة، وإحداثيات للخريطة.

## ترتيب التركيب
1. خذ نسخة احتياطية من Supabase ومن ملفات GitHub.
2. شغّل `supabase_upgrade.sql` في Supabase SQL Editor.
3. راجع الأخطاء الناتجة وسياسات RLS قبل المتابعة. لا تشغّلها على مشروع الإنتاج دون نسخة احتياطية.
4. اربط الواجهة بـ `create_ride_broadcast` عند إنشاء الرحلة، وبـ `accept_ride_broadcast` لقبولها.
5. شاشة المحادثة يجب أن تعرض الرسائل فقط للزبون وصاحب الرحلة المقبول، وتستمع لتحديثات Realtime أو تعيد الجلب دورياً.
6. اختبر بحساب زبون، وسائقين اثنين، ومكتب: أرسل طلباً وتأكد أن الجميع يرونه، ثم اجعل اثنين يقبلان في اللحظة نفسها وتأكد أن واحداً فقط يفوز.

## مهم
- هذا الملف ترقية قاعدة بيانات وليس ضماناً بأن التطبيق الحالي متوافق تلقائياً معها.
- يعتمد على أسماء أعمدة موجودة في المشروع: `profiles.id/role/status/available` و`rides.id/customer_id/pickup/dropoff/status`. راجع مخططك الفعلي قبل التنفيذ.
- لا تتجاوز RLS. لا تضع مفتاح `service_role` في الواجهة.
- إرسال الطلب للجميع يعني كل السائقين والمكاتب الذين حساباتهم `active` وحالة `available=true` وقت إنشاء الطلب. إذا لم يكن هناك أحد متاح فسيبقى الطلب بلا مستلمين، ويجب أن تعرض الواجهة ذلك للزبون.
- لا تحتوي هذه الإضافة على بوابة دفع أو رسائل SMS أو إشعارات Push؛ يلزم إعداد مستقل لهذه الخدمات.
